# CLAUDE.md — Cyprus Road Signs Telegram Bot

Telegram-бот для подготовки к теоретическому экзамену на водительские права на Кипре.
Два режима: карточки (flashcards) с интервальным повторением и тесты (quiz) с подсчётом результата.

## Контекст проекта

- **Основной датасет: `data/signs_full.json` — 234 знака, 13 категорий** (полный перечень
  кипрского кодекса по инвентарю driving.cy). Поля: id, category, name_en, name_ru,
  name_el, image_url (источник), image (локальный путь `assets/img/<id>.<ext>`).
- Греческие названия (`name_el`) взяты с греческой версии того же каталога
  (https://driving.cy/el/signs) скриптом `scripts/fetch_greek_names.py` — это подписи
  самого источника, а не перевод. Для колоды-минимума таблица выверена вручную в
  `scripts/add_greek_mini.py` (см. пометки catalog/adapted/new).
- Изображения НЕ включены в репозиторий — их скачивает `scripts/fetch_images.py`
  (нужен интернет). Затем `scripts/convert_full_images.sh 512` конвертирует SVG → PNG:
  **Telegram не рендерит SVG в сообщениях**. Правило выбора файла в боте:
  если рядом с `image` существует файл с тем же именем и расширением `.png` — использовать его;
  `.jpg`/`.png` оригиналы использовать как есть.
- Вторичный датасет: `data/signs.json` — 63 рукописные карточки (`assets/svg/`,
  конвертация `scripts/svg_to_png.sh`). У них есть поле `explanation_ru` (пояснения).
  Использовать как колоду «Экзаменационный минимум» поверх полного каталога; сопоставление
  с полным каталогом не требуется, это независимая колода.
- Язык интерфейса бота — русский. Изучаемый язык названий выбирается в ⚙️ Настройках:
  английский (по умолчанию) или греческий — экзамен сдаётся на греческом/английском.
  Выбранный язык идёт первой строкой ответа и определяет варианты в тесте; остальные
  языки и русский перевод показываются ниже. Настройка хранится в `user_settings`.

## Технологический стек

- Python 3.11+, **aiogram 3.x** (async, FSM из коробки).
- SQLite через `aiosqlite` — прогресс пользователей. Без ORM, прямой SQL: проект маленький.
- Конфиг: переменная окружения `BOT_TOKEN` (python-dotenv для локальной разработки).
- Деплой: Dockerfile + docker-compose.yml, production-grade (non-root user, healthcheck
  не нужен для polling). Манифесты Kubernetes — в `deploy/k8s/` (kustomize, base + overlays),
  пояснения к решениям в `deploy/README.md`. Ограничение: ровно одна реплика и стратегия
  Recreate — long polling и SQLite на RWO-томе не допускают второго пода.
- Режим работы: **long polling** (не webhook) — проще для self-hosted.

## Функциональные требования

### Команды

- `/start` — приветствие + главное меню (inline-кнопки): «📚 Карточки», «✍️ Тест»,
  «📊 Прогресс», «⚙️ Категории».
- `/cards` — режим карточек.
- `/quiz` — режим теста.
- `/stats` — статистика пользователя.

### Режим карточек

1. Пользователь выбирает категорию (или «Все»).
2. Бот отправляет фото знака (PNG) **без названия** + inline-кнопки:
   «Показать ответ». Формулировка вопроса зависит от типа объекта: «Что это за знак?»,
   «Что это за разметка?», «Что это за сигнал?».
3. После «Показать ответ» — редактирование caption: название **только на выбранном
   языке** + пояснение (если есть), кнопка «➡️ Дальше».
4. «Дальше» продвигает карточку на коробку вперёд и показывает следующую.
   Самооценки нет: вернуть карточку в нулевую коробку может только ошибка в тесте.
5. Кнопка «⏹ Стоп» в каждом сообщении — выход в меню.

### Интервальное повторение (упрощённый SM-2)

Таблица `progress(user_id, card_id, box INTEGER DEFAULT 0, due_at TIMESTAMP)`.
Система Лейтнера, 5 коробок с интервалами: 0 → сразу, 1 → 1 день, 2 → 3 дня, 3 → 7 дней, 4 → 21 день.
- Просмотр карточки («Дальше») → box + 1 (максимум 4), due_at = now + интервал.
- Ошибка в тесте → box = 0, due_at = now (карточка вернётся в ближайшую сессию).
Выборка следующей карточки: сначала карточки с `due_at <= now`, при отсутствии — новые
(нет записи в progress), при отсутствии — сообщение «На сегодня всё повторено 🎉».

### Режим теста

1. Выбор категории и длины теста (10 / 20 / все вопросы категории).
2. Вопрос = фото знака + 4 варианта ответа. Варианты перечисляются в подписи к фото,
   на кнопках только цифры: названия бывают под 60 символов и на кнопке обрезаются.
   Дистракторы — случайные названия **из той же категории** (варианты из одной
   категории сложнее и полезнее); если в категории меньше 4 карточек — добирать из
   колоды, но **только среди объектов того же типа** (знак / разметка / сигнал).
3. После ответа: правильный вариант помечается ✅, ошибочный выбор — ❌ (редактирование клавиатуры),
   краткое пояснение в caption, кнопка «Дальше».
4. Итог: X из N, процент, список ошибок (названия знаков). Ошибочные карточки автоматически
   получают box = 0 в системе повторения — тест и карточки связаны.
5. Порог экзамена на Кипре — держать в тексте итога ориентир: «на реальном экзамене
   нужно ~90% правильных ответов».

### Прогресс

`/stats`: всего карточек изучено (box >= 1), выучено (box == 4), к повторению сегодня,
результаты последних 5 тестов (таблица `quiz_results(user_id, category, score, total, ts)`).

## Нефункциональные требования

- Все PNG загружаются в Telegram один раз, дальше используются `file_id` (кэш в таблице
  `file_cache(card_id, file_id)`), чтобы не гонять байты при каждой отправке.
- Callback data короткие (лимит Telegram 64 байта): формат `c:<action>:<payload>`.
- Один пользователь — одна FSM-сессия; состояние теста хранить в FSM storage (MemoryStorage
  достаточно, при рестарте тест просто начнётся заново — это ок).
- Graceful shutdown по SIGTERM (для Docker).
- Логирование: stdlib logging, INFO, в stdout (для docker logs).

## Порядок работы

0. Подготовка данных: `python3 scripts/fetch_images.py` (все 234 файла должны скачаться,
   при failed > 0 — разобраться до продолжения), затем `./scripts/convert_full_images.sh 512`
   и `./scripts/svg_to_png.sh 512` (63 файла).
2. Создать скелет проекта и БД-слой, прогнать запуск с фиктивным токеном (ошибка авторизации
   от Telegram API — ожидаемый результат smoke-теста без токена).
3. Реализовать меню → карточки → тест → статистику, в этом порядке.
4. Написать README с инструкцией: получение токена у @BotFather, запуск через docker compose.

## Проверка качества

- `python -m py_compile` на все модули; запуск бота с реальным токеном — ручная проверка
  сценариев: полная сессия карточек (все три кнопки самооценки), тест на 10 вопросов
  с минимум одной ошибкой, /stats после этого.
- Убедиться, что повторная отправка того же знака использует file_id (в логах не должно
  быть повторной загрузки файла).

## Явно вне скоупа (не делать без запроса)

- Webhook-режим, платежи, мультиязычность интерфейса, админ-панель, PostgreSQL.
- Изменение дизайна знаков. Если знак нужно поправить — редактировать
  `scripts/generate_assets.py` и регенерировать, а не править SVG вручную.

## Известные ограничения данных

- Русские названия в signs_full.json — переводы английских формулировок, не дословные
  цитаты официального издания Департамента дорожного транспорта Кипра.
- Изображения скачиваются с driving.cy для личного обучения. Сами изображения знаков —
  воспроизведения официальных знаков (гос. стандарт), но при любом публичном
  распространении бота источник изображений нужно пересмотреть (официальное издание
  кодекса или Wikimedia Commons).
- В категориях warden/marking/roundabout изображения — фотографии и схемы (jpg/png),
  а не пиктограммы; для режима теста это нормально.
- У полного каталога нет поля explanation_ru. Пояснения есть только у колоды-минимума;
  добавлять их в полный каталог — отдельной задачей при необходимости.
